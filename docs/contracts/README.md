# Draft API contract (0.2.1-draft)

`openapi.v1.json` is the API-owned contract for `/api/v1` operations. It is generated by `python scripts/generate_contract.py`; `--check` and `scripts/validate_contract.py` run in CI. This draft is **not** the runtime Swagger document. Authentication, assessment, diagram-integration and authenticated health operations are live in Swagger. Stabilize the draft as 1.0.0 only after reconciling every live runtime schema; review breaking changes before updating the web snapshot.

## Transport and access

All business operations require a bearer JWT. `Admin` can manage users and view logs; `Admin` and `Management` can write inventory, deductions and supplier requests; all three roles can read inventory and dashboard. Roles are authorization identifiers and are not translated. The API enforces active account/security-version checks. There is no public registration.

Access tokens last 10 minutes. Browser login with `sessionMode=browser` uses a Secure, HttpOnly, SameSite=Strict refresh cookie (`hi_refresh`) scoped to `/api/v1/auth`, with a 7-day idle and 30-day absolute lifetime. On page load the browser calls `GET /api/v1/auth/csrf` with credentials; the response sets `hi_csrf` and returns its token in `X-CSRF-Token`. Browser login, refresh and logout must send that header and an exact same-origin `Origin`; reject mismatches. CSRF renewal is available before sign-in and after reload, without browser storage of access or refresh tokens. Browser flows require HTTPS, including local development, because Secure cookies do not provide reliable plain-HTTP behavior. An external server client uses `sessionMode=external`, receives a short-lived access token only, and reauthenticates when needed. It must not receive refresh cookies or bypass browser CSRF checks by claiming browser mode.

Lists use `items/page/pageSize/totalCount/totalPages`, with page size at most 10, stable ordering and integer counts serialized as decimal strings. Money is USD, formatted as a two-fraction-digit decimal string; SQLite stores integer minor units. Quantity is an integer from 1 to 2,147,483,647. Nullable optional fields use explicit null, while omitted fields are allowed only where the schema says so. Errors use `application/problem+json` with stable `code`, `traceId` and optional field errors. Mutable GETs return `ETag`; PUT/DELETE require `If-Match` (428 if absent, 412 if stale). Creating a resource returns 201 and `Location`.

The eCommerce deduction endpoint accepts one item, a stable external reference and a caller-scoped printable-ASCII `Idempotency-Key` (1–128 characters). Same key and same request returns the prior result; same key with different request returns 409. A deduction leaving quantity below 1 is rejected with 409. Successful keys remain with history. The Phase 4A implementation commits the conditional quantity update and deduction record atomically. Supplier requests create an order request and outbox record in one transaction; a local adapter/retry worker records delivery. Live supplier delivery remains unconfigured and requires explicit recipient/channel authorization. Request, replay and error examples are embedded in the generated contract.

Active users, warehouses and items are soft-deleted in the database. Active names/emails are unique, while a deleted value can be reused. Historical deductions, supplier requests and sessions retain valid foreign keys. The service layer enforces nonempty-warehouse rejection and bootstrap admin protection.

## Version policy

`/api/v1` is the major compatibility boundary. The draft version is 0.2.1-draft; the first stable release will be 1.0.0 after runtime-schema reconciliation. Additive optional changes raise the minor version; documentation-only corrections raise the patch version. Required-field, removal, semantic or incompatible enum changes need an explicit migration/version decision. Merge a reviewed API contract change first, then update the web snapshot/checksum in its own PR.
