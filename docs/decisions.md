# Accepted foundation decisions

- Two public repositories under Anas-Abukhadir97; backend and frontend are independent sibling checkouts.
- .NET 10 LTS / EF Core 10 / SQLite, React / TypeScript / Vite, N-tier backend. React and .NET 10 supersede the older assessment stack.
- English/Arabic resources, Arabic RTL, stable role identifiers.
- Phase 3 implements 10-minute HS256 JWTs and 7-day-idle/30-day-absolute rotating browser refresh sessions. Access tokens stay in web memory; a refresh family is revoked after reuse or logout. External login issues no cookie. Current account/role/security version is checked on every JWT request.
- Browser login, refresh and logout require exact configured HTTPS Origin and matching CSRF cookie/header. Vite uses HTTPS locally and proxies to loopback HTTP API; production API rejects plain HTTP and requires trusted TLS termination. The development signing key is generated under ignored `src/HappyInventory.Api/data/`; production requires an explicit signing key.
- SQLite triggers protect the bootstrap administrator from deletion, deactivation and demotion, and bump security version on password/role/active/deletion changes. Login has a per-IP fixed-window limit and per-account lockout. User-management routes are live in Phase 4.
- `/api/v1` also uses per-IP, per-process fixed-window limits for reads and writes, with a separate stricter login limit. Health probes and static assets do not consume API permits. A trusted reverse proxy supplies the client IP; the app does not accept arbitrary forwarded headers. Responses use localized problem details and `Retry-After`.
- Phase 4 routes implement the draft warehouse/item/user/dashboard/log shapes. Inventory writes require Admin or Management; user management and logs require Admin. Updates/deletes require a strong GUID `If-Match` ETag. Active records use soft deletion, and lists enforce a 10-row maximum. Serilog retains 14 daily/size-rolled JSON log files under ignored runtime data; request bodies, credentials and authorization headers are not logged.
- Global item-name uniqueness, quantity >=1, decimal prices represented as minor units internally and decimal strings externally; ETag concurrency is enforced on CRUD writes.
- Phase 2 added SQLite migrations and first-admin seeding, a draft OpenAPI generator/validator, and contract drift checks in CI. Phase 6 added non-root images, independent GHCR publication, a tested digest pair, persistent Compose and backup/restore. Azure is final Phase 8 after cost approval.
- Active users, warehouses and items use soft deletion so audit, refresh, deduction and supplier records retain valid foreign keys. Active names/emails remain unique; a deleted name/email may be reused. Application services must enforce protected-admin and nonempty-warehouse deletion rules.
- No software license selected yet. Original assessment documents and private planning material remain outside both repositories.
- Notification updates remain on authenticated server-sent events while the hub is server-to-browser only. The current fetch stream sends the bearer token in a header, keeps the notification list in SQLite, and reconnects after token refresh. Reconsider SignalR if the product needs browser-to-server live calls, multiple real-time feature types, or a supported scale-out backplane; its browser WebSocket/SSE client can send access tokens in the query string.
- API service and host registrations live in `ServiceRegistration.cs`; `Program.cs` defines the middleware and endpoint order. A centralized exception handler returns a localized, sanitized problem response for unexpected failures, while expected business failures retain their existing response contract.
