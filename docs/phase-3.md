# Phase 3 authentication

Live endpoints: `GET /api/v1/auth/csrf`, `POST /api/v1/auth/login`, `POST /api/v1/auth/refresh`, `POST /api/v1/auth/logout`, and bearer-protected `GET /api/v1/auth/me`. The rest of the draft contract remains planned. Browser mode requires an exact HTTPS Origin and matching CSRF cookie/header. Its refresh cookie is host-only, Secure, HttpOnly, SameSite=Strict and scoped to `/api/v1/auth`. External mode returns only a 10-minute JWT and no refresh cookie.

Refresh tokens contain 384 random bits. SQLite stores only SHA-256 hashes and family links. A transaction consumes each token once and creates its successor; old-token reuse revokes the full family. Logout, expiry, account disable/delete, role/password changes and family revocation invalidate access on the next request. Database triggers protect the bootstrap administrator and automatically bump user security versions for sensitive changes. Login uses a per-IP 10/minute limit and a per-account five-failure/15-minute lockout. Production requires a signing secret and HTTPS; local Vite HTTPS proxies to the loopback API.

Tests cover local and external login, CSRF and Origin rejection, rotation/replay, simultaneous redemption, logout, expiry, account changes, bootstrap-admin constraints and rate limiting on the real SQLite migrations. User-management endpoints are Phase 4; their changes must use the security-version trigger and may explicitly revoke session families for immediate cleanup. Trusted proxy configuration is a deployment task for Phase 8. Live supplier delivery remains unconfigured.

Local verification on 17 October 2026: locked restore, draft contract generation/validation, Release build without warnings, formatting, and 31 integration tests passed. Through the live Vite HTTPS proxy, CSRF bootstrap returned 204, browser login and `/auth/me` returned the Admin role, refresh returned a different access token, and logout returned 204. No token value was printed by the smoke test. Hosted CI evidence is on the Phase 3 PR.
